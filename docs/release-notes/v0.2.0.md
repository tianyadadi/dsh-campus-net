# v0.2.0 — 黑洞网卡检测

这一版只加一件事：**揪出「挂着默认路由却走不通」的网卡**，并在挂件上修掉它。

## 为什么加

2026-11-03 那晚，模型一直报 `transport failed` / `Request timed out.`，
三家服务商（阿里云、暴喵、官方）**同时**挂，每次刚好卡 10 秒，重试 5 次全灭。

查下来跟服务商一点关系都没有：

- 校园网登出后，那张网卡还是 up 的、默认路由也还在
- WiFi 一抖，系统把流量切过去 → SYN 没人应答
- Node 的 undici 默认连接超时正好是 10 秒 → 客户端自己放弃
- 证据：同一时刻直接打端点 0.6~1.8 秒正常；绑源 IP 实测那张网卡 21 秒超时；
  WLAN 事件日志显示断线时段与失败时段完全重合

## 新增

- **黑洞探测** —— 绑定每张候选网卡的源 IP 去连 `223.5.5.5:443`，1.5 秒连不上即判定。
  只看 ping 不够：校园网网关 0ms 能通，但没认证照样出不去。结果缓存 60 秒。
- **挂件提示** —— 折叠态圆点变黄；展开后有黄色说明 + 两个按钮：
  - **修一下**：跃点抬到 9999（弹一次 UAC）；DNS 只有在该网卡是静态配置时才重置，
    若是 DHCP 下发则跳过并明说 —— 重置只会把同一批死 DNS 再拿回来（实测踩过）
  - **还原跃点**：跃点交回系统自动
- **新接口** —— `GET /api/campus-net/dead-path`、`POST /api/campus-net/fix-path`、
  `POST /api/campus-net/restore-path`
- **新命令** —— `python core/campus_net.py dead-path | fix-path | restore-path`

## 为什么是抬跃点而不是禁用网卡

禁用之后要回校园网还得去设备管理器手动开，太重。
抬跃点只是让它永远抢不过当前网络 —— 插上网线照样能用，只是优先级靠后。

## 兼容性

`status` 的返回多了个 `dead_path` 字段，老前端忽略它即可，不影响任何已有行为。

## 安装 / 升级

```bash
dsh plugin --profile desktop add link:<本目录绝对路径>
```

升级后**重启 DSH**（新增了服务端路由，bundle 层要重启才组装）。
